# avmax personal VPN

Self-hosted split-tunnel VPN for a Moscow home (Keenetic Giga, MacBook, iPhone) with a foreign exit node,
DPI resistance (VLESS + Reality + Vision on 443 behind a real website, AmneziaWG as the UDP fallback) and a
Moscow node for travelling. Design and research notes: `~/.claude/plans/i-wanna-set-up-majestic-swing.md`.

## How it behaves

| Where | State | Russian destinations | Foreign destinations | Switch |
|---|---|---|---|---|
| Home Wi-Fi (router does it, no apps) | `vpn-mode on` | direct | EU node | one tap: Shortcut → SSH to the router |
| Home Wi-Fi | `vpn-mode off` | direct | direct | same |
| Mac/iPhone away (cellular, other Wi-Fi) | auto (Shadowrocket On Demand) | direct | EU node | nothing to tap |
| Mac/iPhone abroad | `... ABROAD` server selected | Moscow node (via EU) | EU node | pick the server in Shadowrocket |

Rules are three layers, first match wins, same on every device: `rules/custom.json` overrides → automatic geo detection
(`geosite:category-ru`, `.ru/.su/.рф`, `geoip:ru`) → everything else via VPN. See `rules/README.md` and `rules/expand.py`.

## Layout

```
ansible/            site.yml + roles base, caddy, xray, awg, awg-link (idempotent, Ubuntu 24.04)
inventory/          hosts.yml (copy from hosts.example.yml)
secrets/            secrets.yml generated by scripts/init-secrets.py (gitignored, back it up)
clients/gen.py      writes clients/out/: URIs + QR, Shadowrocket rules + RU rule-set, Happ profile, AWG confs, subscriptions, XKeen configs
rules/              custom.json (your overrides), expand.py (grow a list from one domain, optional Claude step)
router/             Keenetic: XKeen install guide (no-policy mode), vpn-mode (on router), keenetic-policy.sh (RCI), Shortcuts recipes
tests/              remote.sh (run on the test Mac), recon.sh, matrix.sh, availability.sh (from the VPS), leak-check.sh, RESULTS.md
```

## Runbook

### 0. Once, on the Mac
```bash
python3 -m venv .venv && .venv/bin/pip install ansible pyyaml cryptography "qrcode[pil]"
.venv/bin/python scripts/init-secrets.py
```
Edit `ansible/group_vars/all/main.yml`: `vpn_domain` (e.g. `eu.yourdomain.tld`), `acme_email`.

### 1. Phase 0: recon on the test Mac, no money spent
This Mac stays on its own tunnel; a second Mac with Remote Login enabled runs every test (`tests/remote.env`):
```bash
tests/remote.sh recon home                 # test Mac on home Wi-Fi
tests/remote.sh recon mobile --detached    # then tether the test Mac to the iPhone; later: tests/remote.sh collect
```
Read `tests/out/recon-*.md`: controls (Hetzner, Vultr, ...) are expected to stall; candidates that download at full speed on both
networks go on the shortlist.

### 2. Phase 1: rent hourly candidates and shoot them out
1. Rent 2–3 VPSes (2 vCPU / 2 GB, Ubuntu 24.04, hourly/daily billing) from the shortlist — VDSina Amsterdam and UpCloud Helsinki
   first (Timeweb Cloud is out: its foreign IPs are seen as Russia by Google and Cloudflare); put them in
   `inventory/hosts.yml` under `eu_candidates`. Point the DNS A record `vpn_domain` at the first one.
2. Set `test_mode: true` in `ansible/group_vars/all/main.yml` (opens the plain-WireGuard control port + iperf3).
3. Deploy and generate client material:
   ```bash
   cd ansible && ../.venv/bin/ansible-playbook site.yml -l eu_candidates && cd ..
   .venv/bin/python clients/gen.py
   ```
   First login on RU hosters is usually root + password: add `ansible_ssh_pass` to the host for the first run;
   the base role installs your key and disables password logins.
4. Per candidate: DPI/stability from the test Mac and service availability from the VPS itself:
   ```bash
   tests/remote.sh matrix vdsina-ams home       # add "quick" for a 3-minute smoke run; the AWG/WG legs prompt you on the test Mac
   tests/remote.sh matrix vdsina-ams mobile --detached   # test Mac tethered to the iPhone; collect later
   tests/availability.sh vdsina-ams             # OpenAI, Claude, Netflix, YouTube Premium, Google, geolocation
   ```
   Paste the summaries into `tests/RESULTS.md`. Repeat the matrix once in the evening (21:00–00:00 Moscow).
5. Keep the winner: move it to group `eu` (optionally the runner-up to `standby`), destroy the rest,
   set `test_mode: false`, redeploy, regenerate clients.

### 3. Phase 2: Mac (test Mac first, then this one)
- Shadowrocket (Mac App Store, non-RU Apple ID): add the subscription from `clients/out/SUBSCRIPTION-URLS.txt` (mac line), then
  import the rules with `open "$(cat clients/out/shadowrocket-import-url.txt)"` (or paste the URL into Shadowrocket → Config → Add).
  Settings → On Demand: Cellular → Connect; Wi-Fi SSID = home → Disconnect; other Wi-Fi → Connect (`router/shortcuts.md`).
- AmneziaWG app as fallback with `clients/out/mac/awg-<server>.conf`. Optional second client: Happ with `clients/out/happ/routing-split.png`.
- Verify on the test Mac with `tests/leak-check.sh` (connected: RU view = ISP, foreign view = EU IP; on the home SSID: disconnected).
  Only then repeat on this Mac and switch the commercial Amnezia service off.

### 4. Phase 3: iPhone
Shadowrocket (non-RU App Store) with the iphone subscription line, the same rules URL and On Demand rules; AmneziaWG app with
`clients/out/iphone/awg-<server>.png`. Verify on Tinkoff Mobile with `tests/leak-check.sh` from a tethered Mac or by eye (ip.beget.ru / ifconfig.co).

### 5. Phase 4: Keenetic (whole home)
`router/xkeen-install.md`. After it, the Macs and the iPhone disconnect automatically on the home SSID and the router takes over.

### 6. Phase 5: Moscow node
Rent the cheapest Moscow VPS, add it to `inventory/hosts.yml` under `msk`, then:
```bash
cd ansible && ../.venv/bin/ansible-playbook site.yml -l msk && ../.venv/bin/ansible-playbook site.yml -l eu -e msk_link_enabled=true && cd ..
.venv/bin/python clients/gen.py
```
Set `msk_link_enabled: true` in group_vars to make it permanent. Test from home with the ABROAD server entry:
2ip.ru must show the Moscow VPS IP, ifconfig.co the EU IP.

## Operations
- **IP got blocked**: rent a VPS in another AS → add to `eu` (or promote `standby`) → `ansible-playbook site.yml -l eu` →
  move the DNS record → `clients/gen.py` → clients pull-to-refresh the subscription. About 20 minutes.
- **Rotate secrets**: `scripts/init-secrets.py --force`, redeploy, re-enrol every device.
- **Upgrading Xray**: bump `xray_version` only after Happ and XKeen ship a core that handles the X25519MLKEM768
  key share (Xray ≥ 26.9.8 requires it); keep the client core ≥ server core.
- **Geo data** refreshes weekly on the server (`xray-geo-update.timer`); Happ fetches its own from runetfreedom; Shadowrocket pulls
  `ru-direct.list` from the subscription URL; the router updates with `xkeen -ug`.
- **Rules**: edit `rules/custom.json` (or `rules/expand.py <domain> --apply direct|proxy`), run `clients/gen.py`, redeploy
  (`ansible-playbook site.yml -l eu`), copy the XKeen files to the router. Clients refresh the rule-set on their next update.
- Server exposes only 80/tcp (real site + ACME), 443/tcp (Reality, real site to everyone else), one UDP port (AWG), key-only SSH.

## Known limits
- Home ISP is MGTS with native IPv6: the router phase must switch IPv6 off (or proxy it), otherwise AAAA-enabled foreign sites leak past the tunnel.
- Mobile "whitelist" shutdowns: no foreign server is reachable, by design of the shutdown.
- Russian platforms degrade users seen from foreign IPs: keep Split as the default.
- KN-1010/1011 Gigas top out around 250–300 Mbps through XKeen.
